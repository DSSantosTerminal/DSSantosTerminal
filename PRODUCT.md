## Platform

web

## Stack

GitHub profile README: `README.md` rendered by GitHub's sanitized Markdown (no custom CSS, no JS, no `style` attributes). Visual material is hand-authored SVG committed under `assets/`, embedded with `<img>` / `<picture>` (animation lives inside the SVG; light/dark variants via `prefers-color-scheme` sources). Self-hosted assets preferred over third-party image services.

## Users

All audiences equally: recruiters and hiring managers (especially transit/mobility tech), fellow developers browsing repos, and the transit community (agencies, GTFS/open-data people). They arrive at github.com/DSSantosTerminal, scan for a few seconds, and decide whether to follow, reach out, or dig into repos.

## Product Purpose

Daniel Santos's GitHub profile page: introduce a fullstack developer who works in public transit and is a transit enthusiast, so a visitor leaves knowing who he is, what he builds, and how to reach him.

## Positioning

The account name is a double meaning nobody else can copy: **DSSantos Terminal** is both a transit terminal and a programming terminal. The profile lives exactly where transit systems meet code.

## Operating Context

Viewed inside GitHub's profile UI, in both light and dark themes, on desktop and the GitHub mobile app/web at ~390px wide. Content area is ~830px wide on desktop. Animated SVGs play when loaded through GitHub's image proxy.

## Product Principles

1. Transit first, code always visible: every transit device should also read as a piece of programming.
2. Truthful board: only real facts appear on the "departure board"; unknowns are shown as coming soon, never padded.
3. Legible in seconds, rewarding on a second look.
4. Self-hosted and durable: assets live in the repo, not on services that can disappear.

## Accessibility & Inclusion

Every image carries meaningful alt text containing its information; animations are decorative and the page must read fully with them static. Text contrast meets WCAG AA in both GitHub themes.
